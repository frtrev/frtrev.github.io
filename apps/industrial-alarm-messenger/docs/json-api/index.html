JSON TCP API

Transport

Connect by TCP/IPv4 to the configured private address and port, default 5050. Each request and response is one UTF-8 JSON object terminated by LF. Frames may arrive fragmented. Maximum frame size is 65,536 bytes.

Every request requires an API key, unique request ID, ISO-8601 timestamp within the configured tolerance, and a known command.

{
  "apiKey": "base64url-secret",
  "requestId": "mill-7-000042",
  "timestamp": "2026-07-26T03:12:25Z",
  "command": "sendAlarm",
  "groupId": "maintenance",
  "priority": "critical",
  "message": "Rolling Mill Cooling Water Pressure LOW"
}
Keep the API key secret, restrict allowed CIDRs, synchronize clocks, and never expose the TCP listener to the public Internet.

Commands

  • ping — connectivity and server time
  • status — readiness and daily statistics
  • sendAlarm — send an alarm to an enabled group
  • listGroups and getGroup — inspect enabled group configuration
  • getStatistics — sent, failed, and total daily counts
  • createGroup, updateGroup, deleteGroup, and exportLogs — require adminPin

Alarm priorities

information, warning, critical, and emergency. Messages are limited to 1,600 characters. Telephone numbers are never accepted by sendAlarm.

URLs in alarm messages

Alarm URLs are disabled by default. An administrator may enable Allow local-network URLs in alarms under TCP and security rules for links to trusted local IBA trends or facility documents.

When enabled, each link must use http or https, use a canonical literal IPv4 address, use an RFC-private, link-local, or loopback destination, and match at least one administrator-configured allowed CIDR.

{
  "message": "IBA trend: https://192.168.68.20/trends/pump-4"
}

Public addresses, hostnames, www links, non-HTTP schemes, embedded user information, and disguised IPv4 forms are rejected before any SMS attempt. The response uses url_not_allowed, and the attempt is recorded as a security failure.

Validation covers the initial destination. Administrators must ensure trusted local servers do not redirect recipients to public or untrusted sites. Recipients need facility-network or authorized VPN access to open these links.

Group fields

groupId and each member’s E.164 phoneNumber are required. Group name, description, member name, and member role are optional and may be blank.

Common errors

missing_credentials, invalid_api_key, unauthorized_ip, expired_timestamp, duplicate_request, malformed_json, unknown_command, administrator_required, group_not_found, group_unavailable, no_recipients, invalid_priority, and url_not_allowed.
