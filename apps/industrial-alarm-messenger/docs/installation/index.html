Commissioning guide

Installation

Device requirements

  • Android: Android 7.0 or newer phone with telephony/SMS support and an active SIM
  • iPhone: iOS 18.2 or newer with cellular service; production critical SMS requires Apple’s Critical Messaging entitlement and authorization for every recipient
  • Continuous iPhone background intake: Apple’s Local Push Connectivity entitlement and the embedded App Push Provider configuration
  • Static DHCP lease or reserved facility Wi-Fi address
  • Private, firewalled automation network
  • Supervised, preferably UPS-backed power

Common commissioning checklist

  1. Open Administrator, use the initial PIN, and change it immediately.
  2. Regenerate the API key before production use and copy it only to authorized clients.
  3. Create groups and recipients using E.164 telephone format such as +15551234567.
  4. Restrict allowed CIDRs to specific automation subnets.
  5. Leave alarm URLs disabled unless recipients require trusted local IBA trends or documents. If enabled, verify each literal IPv4 destination against the allowed CIDRs.
  6. Assign a stable local address and document the TCP port.
  7. Send ping, then a non-critical test alarm; verify SMS behavior and audit records.
  8. Export and retain the commissioning log.

Android commissioning

  1. Install the Android release on the dedicated phone.
  2. Disable battery optimization for the app.
  3. Grant SMS, phone/SIM, local network, and notification permissions.
  4. Start the gateway and confirm its persistent foreground notification.

iPhone commissioning

  1. Install a correctly signed iPhone release containing the approved entitlements and embedded App Push Provider.
  2. Grant Local Network access.
  3. Open Critical Messaging authorization in Settings and authorize every enabled recipient.
  4. Configure and enable the Local Push Connectivity provider for continuous background intake.
  5. Verify provider status, then perform an end-to-end alarm test with the app backgrounded and the screen locked.
Entitlements are deployment requirements, not ordinary runtime permissions. If Apple has not granted Critical Messaging, the app cannot send unattended critical SMS. If Local Push Connectivity is unavailable, the iPhone can manage groups and authorization but cannot promise continuous local alarm intake while the main app is suspended.

Hardening

  • Isolate the phone and trusted clients on a dedicated VLAN.
  • Block access from guest Wi-Fi, user networks, and the public Internet.
  • Rotate the API key after personnel or equipment changes.
  • Store the administrator PIN in the facility credential vault.
  • Restrict physical access and enable device encryption and screen lock.

Local alarm links

Alarm URLs are blocked by default. An administrator may enable local-network URLs under TCP and security rules. Only http and https links using canonical literal private IPv4 addresses inside an allowed CIDR are accepted. Hostnames, public addresses, disguised IP forms, and other schemes are rejected and logged as security failures. Recipients must be connected to the facility network or an authorized VPN to open local links.

Continuous operation

On Android, the persistent Industrial Alarm Gateway running notification indicates that the foreground service is active. On iPhone, continuous background operation is provided by the approved Local Push Connectivity provider rather than an ordinary background TCP server. Validate background and screen-off behavior on the exact managed device and repeat the test after operating-system updates.

Review the safety disclaimer before commissioning.
